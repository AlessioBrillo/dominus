# Mobile release runbook

Status: **executed up to the PWA gate; store submission is an operator task**
(ADR-0114, ADR-0116, ADR-0117). This file records what is already in the code
and what a human still has to do. It is deliberately concrete: a store
submission is a sequence of external actions, not a feature flag.

## What shipped in the repository

- A five-tab mobile shell (Today, Appraise, Holdings, Alerts, Account) inside
  the existing React SPA. The desktop dashboard remains intact and is still
  the route at `/` — the decision inbox is rendered above its stats.
- An installable PWA: manifest, maskable icons, app-shell service worker,
  offline navigation fallback and Web Push handlers.
- `GET /api/v1/mobile/today`: one response with alerts, renewals and
  watchlist changes, plus an explicit `evidence` contract (ADR-0115).
- Per-device bearer credentials: `POST/GET/DELETE /api/v1/mobile/devices`,
  validated by `DeviceTokenProvider` before any tenant context exists.
- Push opt-ins: `GET/PUT/DELETE /api/v1/mobile/push`, VAPID keys from the
  environment, and `WebPushNotifier` wired into the tenant notification
  chain with per-topic filtering.
- A store build variant (`VITE_APP_VARIANT=store`) that compiles prices,
  checkout and signup out of the bundle.
- Capacitor configuration and build scripts. The native projects are
  generated at store time, not committed to the repository.

## Phase A — public PWA (current gate)

Operator tasks, in order:

1. Choose and register the canonical domain (the old `dominus.app` is parked).
2. Apply Terraform with remote state and a closed-by-default ingress
   ([first-apply.md](../deployment/first-apply.md)).
3. Configure SMTP, `PUBLIC_APP_URL`, and add the PWA origins to CORS:
   `CORS_ORIGIN=https://app.<domain>,capacitor://localhost,https://localhost`.
4. Generate VAPID keys (`node scripts/generate-vapid-keys.mjs`) and set
   `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
5. Run `npm run gate`, `npm run gate:docker`, `npm run launch:check --cloud`
   and the stranger test of ADR-0112.
6. Keep `CLOUD_PAID_ENABLED=false` until the identity and fiscal position
   are complete (ADR-0108, ADR-0118).

Exit gate: the funnel targets of
[founding-cohort.md](founding-cohort.md) are met — at least 20 design
partners have made a real keep/drop decision.

## Phase B — design partners and evidence

No new store code is needed. Instrument the first-party funnel, watch the
activation targets, and record the willingness-to-pay answers. Do not
proceed to a store until the activation gate is green: a store app cannot
create demand that the web product has not already demonstrated.

## Phase C — Capacitor and the stores

1. From `frontend/`, run `npx cap add android` and `npx cap add ios`. Native
   projects are generated by Capacitor; iOS needs macOS (a cloud runner is
   the chosen path, see ADR-0117).
2. Add a secure-storage plugin when one is verified against Capacitor 8.
   `src/lib/secure-storage.ts` detects it at runtime; until then the token
   lives in `localStorage` and the store build has no keychain guarantee.
   Native FCM/APNs push is likewise **not implemented**: only browser push
   works, so a store build cannot show a working notification opt-in until
   that follow-up increment ships with vendor credentials.
3. Build the store bundle:
   `MOBILE_API_URL=https://app.<domain> npm run mobile:build`
   (from `frontend/`). This compiles prices and checkout out.
4. Store review checklist:
   - App Store 4.2 minimum functionality: native push, biometrics and share
     must be present before submission — browser push alone is not enough
     (all three are follow-up work, see step 2);
   - App Store 3.1.1 and Google Play payments: no price, checkout or
     upgrade button in the app; the account screen shows plan + data rights;
   - account deletion reachable in-app (already in Account → Your data);
   - privacy labels / data safety form from the published privacy notice;
   - privacy policy URL, support URL, encryption export declaration;
   - deep links (`/alerts`, `/portfolio`, `/score/...`) and push tap-through.
5. Google Play: new personal accounts need 12 testers for 14 days before
   production. Apple Developer and Play Console accounts are budgeted as a
   one-off cost in the launch plan.
6. Ship Android first; iOS follows on the macOS runner. The store build is
   a compile-time variant — there is no second UI codebase.

## What is deliberately not in the app

Prices, checkout, in-app purchase, the pipeline builder, backtest, provider
configuration, the operator admin panel and the full 34-page desktop
navigation. They remain web-only (ADR-0114, ADR-0117).
